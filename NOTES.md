# Робочі нотатки

## ЛР 1. Платформа .NET і перший застосунок

- `dotnet --version` → 10.0.401 (SDK, а не Runtime: потрібні компілятор і шаблони).
- `dotnet run` = `dotnet restore` + `dotnet build` + запуск. У Windows вивів `Платформа: Microsoft Windows 10.0.19045`.
- Без рядка `Console.OutputEncoding = UTF8` у консолі Windows українські літери можуть перетворитися на «?». У macOS і Linux термінал і так працює в UTF-8.
- `bin/` і `obj/` — результати збирання; вони щоразу створюються заново й на іншій машині будуть іншими, тому їх виключено в `.gitignore`.

### Відповіді на «Перевірте себе»
1. SDK = середовище виконання + компілятор + шаблони + команда `dotnet`. Для розробки потрібен SDK, Runtime лише запускає готові програми.
2. `TargetFramework` (`net10.0`) — версія платформи, під яку збирається проєкт.
3. `bin` і `obj` генеруються під час збирання, важать багато й залежать від машини.
4. `dotnet run` відновлює пакети, збирає проєкт і запускає результат.
5. `Console.OutputEncoding` вмикає UTF-8 у консолі. Без нього проблема в Windows.
6. Код компілюється в проміжну мову (IL), яку середовище виконання перетворює на машинний код на цільовій машині. Отже, однаковий вихідний текст. Відмінності є там, де програма звертається до системи: файли, шляхи, кодування, вікна.

## ЛР 2. C# з нуля: типи, рядки, колекції

- Основний тип `Transaction` (каталог `Transactions/`) має 4 властивості: `Id`, `Description`, `Amount`, `Account`, а також два конструктори. Конструктор без параметрів знадобиться для читання з JSON у ЛР 5.
- `Amount` має тип `decimal`, а не `double`. Для грошей потрібна точна десяткова арифметика: у `double` 0.1 + 0.2 ≠ 0.3.
- Поки що метод `BelongsTo(account)` звіряє рахунок, який увів користувач, із рахунком операції. Спільна дія `BalanceEffect` з різною поведінкою для витрати, надходження й переказу з'явиться в ЛР 3.
- Число в рядку виводиться за правилами поточної культури: `642,50` з комою, бо в системі українська культура.

### Досліди з порівнянням рядків
Уведення за рахунком «Картка» (у журналі є 3 операції):

| Уведено | `CurrentCultureIgnoreCase` | `Ordinal` |
|---|---|---|
| `Картка` | 3 операції | 3 операції |
| `картка` (мала літера) | 3 операції | не знайдено |
| `  Картка` (пробіли на початку) | 3 операції | 3 операції |

Пробіли не заважають в обох випадках, бо перед порівнянням викликається `Trim()`. Регістр важливий лише для `Ordinal`.

**Висновок для моєї теми:** назву рахунку вводить людина, тому потрібне порівняння за правилами мови без урахування регістру (`CurrentCultureIgnoreCase`). Суми порівнюються як числа `decimal`, а не як рядки, і для них питання регістру немає. `InvariantGlobalization` у проєкті не вмикаю, інакше зникне ICU з правилами української мови.

### Відповіді на «Перевірте себе»
1. Поле — це змінна всередині об'єкта. Властивість — пара дій get/set над полем, через яку контролюється доступ.
2. Конструктор без параметрів потрібен серіалізатору JSON (ЛР 5), щоб створити порожній об'єкт і заповнити властивості.
3. `List<Transaction>` — список лише з операцій. Інший тип компілятор не пропустить уже під час збирання.
4. Рядок не змінюється: `Trim()` повертає новий рядок, а старий лишається як був.
5. `Ordinal` звіряє коди символів: це швидко й однаково скрізь, підходить для ідентифікаторів. Порівняння за правилами мови враховує абетку й регістр, підходить для тексту, який вводить людина.
6. ICU — бібліотека правил мов. Її версія залежить від системи, а в мінімальному образі Linux її може не бути взагалі.
